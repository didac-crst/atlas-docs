# AtlasDocs v0.4 — Semantic Workbench

## Status

Implemented on the v0.3 Entity + ExternalReference core. No schema migration.

## Goals

- General entity-oriented relationship API (not only document→concept).
- Deterministic Paperless reconciliation without automatic deletes.
- Classification workbench improvements (metadata + reconcile UI).

## Preserved invariants

- Paperless remains document authority; REST-only integration.
- AtlasDocs UUID identity; Paperless ids via `ExternalReference(system=paperless)`.
- Entity-to-entity N:N relationships with directionality, inverses, provenance, status.
- Paperless authorization filtering (denial → not found; no semantic leak).
- `/documents/{paperless_id}` facade remains compatible.
- React SPA under `/ui` with HttpOnly session + CSRF BFF (`/ui/api/*`).

## API additions

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/entities/{entity_id}` | Entity detail + outgoing relationships |
| GET | `/entities/{entity_id}/relationships` | Outgoing relationships only |
| POST | `/entities/{entity_id}/relationships` | Create edge (concept, entity, or Paperless target) |
| DELETE | `/relationships/{relationship_id}` | Delete edge (+ symmetric/inverse companions) |
| POST | `/reconcile` | Run reconciliation (`dry_run`, optional `limit`) |

Document facade (unchanged paths):

- `GET/POST /documents/...`
- `GET /documents?unclassified=true`

### POST `/entities/{id}/relationships` body

Provide **exactly one** target:

```json
{"relationship": "source-country", "target": "germany"}
{"relationship": "derived-from", "target_paperless_id": 185}
{"relationship": "related-to", "target_entity_id": "<uuid>"}
```

Optional: `origin`, `status` (defaults `manual` / `confirmed`).

Duplicates → **409**. Invalid targets/types → **422**. Missing/unauthorized Paperless-backed entities → **404**.

## Seed expansions

Concept ontologies: `country`, `document-type`, `person`, `organization`.  
Relationship types include directed classify edges, `related-to` (symmetric), and `derived-from` / `has-derivative` (inverse pair) for document↔document edges.

## UI

The classification workbench is a React + TypeScript + Vite SPA served from the
FastAPI container under `/ui`, with a session/CSRF BFF at `/ui/api/*`.

Jinja server-rendered interaction was retired; there is no production Jinja fallback.

See `docs/frontend-architecture.md`, `docs/v0.4-react-ui-proposal.md`, and
`docs/atlasdocs-ui-brand-direction.md`.

## CLI

```bash
atlasdocs reconcile --dry-run
atlasdocs reconcile --limit 100
PAPERLESS_TOKEN=... atlasdocs reconcile --json
```

See `docs/reconciliation.md`.

## Explicitly deferred

LLMs, MCP, embeddings, graph visualization, native notes, sidecars, Evidence, Supernova, bulk legacy migration, automatic deletion, background workers, webhooks.

## Known limitations

- Person/Organization are concept entities (not separate `EntityType` values).
- Paperless correspondent/type labels appear only when the REST payload includes names (not bare foreign-key ids).
- Document↔document edges in the UI use a Paperless id target for `derived-from` / `has-derivative` (and reply pairs).
