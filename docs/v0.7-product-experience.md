# AtlasDocs v0.7 Product Experience and Entity Lifecycle

## Status

Active sprint specification for the public AtlasDocs repository.

Read together with the [product experience specification](product-experience-spec.md),
[product identity](product-identity.md),
[document lifecycle](document-lifecycle.md), and the [v0.6 Explore contract](v0.6-explore-semantic-workbench.md).

Update [roadmap.md](roadmap.md) as phases land.

## Sprint goal

Make AtlasDocs feel like an entity-centered semantic application rather than a
document queue with semantic fields. Establish lifecycle and navigation
foundations without implementing the complete future knowledge graph.

## Product direction

```text
Evidence is the foundation of trust.
Master Data is the foundation of knowledge.
Entities and relationships are the primary navigation model.
Paperless is reused wherever it already solves the problem well.
```

Paperless remains authoritative for OCR, storage, document versions, permissions,
previews, downloads, and physical document lifecycle.

AtlasDocs is authoritative for semantic identity, relationships, ontology,
navigation, provenance, and knowledge discovery.

## Already shipped (v0.6 — do not rebuild)

- Home | Explore | Classify | Ingest; Account menu for Reconcile / Disconnect
- Explore modes, entity detail with backlinks, semantic completeness
- Inline preview / download BFF; replace preserving UUID; hard delete → tombstone
  (v0.7 replaces Evidence hard-delete-only with trash → restore → permanent delete)

## Lifecycle categories

Every entity has an explicit lifecycle category:

```text
Evidence | Master Data | Organizational
```

Category is stored or deterministically derived from entity-type registry
configuration. It must not be inferred only from labels (e.g. “Contract”).

| Category | Examples | Typical operations |
| --- | --- | --- |
| Evidence | Paperless-backed documents | create, replace, trash, restore, permanent delete |
| Master Data | Person, Organization, Country, Concept | rename, archive, restore; merge contract; no casual delete while linked |
| Organizational | Case | archive / reorganize with provenance intact |

## Master Data merge (v0.7 depth)

Merge is **contract + safe placeholder** this sprint: block destructive delete
while relationships exist; expose data-model/API redirect fields; no full merge
UI. A misleading delete control must not ship.

## Paperless download variants

AtlasDocs BFF must preserve Paperless version-aware downloads:

```text
/api/documents/{paperless_id}/download/?original=true&version={version_id}
/api/documents/{paperless_id}/download/?version={version_id}
```

`version_id` is a Paperless version identifier, not an AtlasDocs UUID. The
browser never receives Paperless tokens or direct authenticated Paperless URLs.

## Implementation phases

### Phase A: lifecycle category foundation

Establish `Evidence | Master Data | Organizational` on entities via registry
config and durable state. Expose category on APIs; gate operations server-side;
reflect category in UI actions.

Implemented: migration `0010_lifecycle_categories`; registry + entity fields;
API/UI expose category; Evidence/Master Data operation gates.

### Phase B: canonical cards and Explore IA

Explore top-level **Documents | Knowledge** (Knowledge hosts People,
Organizations, Countries, Cases, Concepts). Shared canonical cards reused in
Explore, search, and relationship picker. Retire flat mixed “All” as the primary
browse mode.

Implemented: Documents | Knowledge Explore IA with knowledge subtypes; shared
`ExploreResultCard` with type chip, relationship count, and preview thumbnails.

### Phase C: version-aware document experience

BFF download variants (`original` / `version`), Download original / Download
selected version UI when metadata exists, and progressive disclosure for
Metadata, OCR, History, and Versions.

Implemented: BFF `original`/`version` query forwarding; document versions on
detail responses; progressive disclosure sections on document detail.

### Phase D: Evidence trash lifecycle

```text
Move to Trash -> Restore -> Delete Permanently
```

Derive active/trashed/purged from Paperless; keep Atlas tombstones for purged.
Preserve replace semantics. No independent Atlas trash system.

Implemented: Paperless trash/restore/permanent delete client + service; UI
actions; tombstone on permanent delete.

### Phase E: Master Data safeguards

Rename, archive, restore; block delete while relationships exist; merge/redirect
data model + API contract + safe placeholder. Organizational archive with
provenance. Completeness updates on archive/restore.

Implemented: rename/archive/restore APIs + UI; merge placeholder redirect;
DELETE entity returns 409 while linked.

### Phase F: collection reconciliation, hardening, docs

Collection-level reconcile for active / trashed / purged; completeness audit on
create/add/remove/replace/archive/restore; browser/a11y/destructive tests;
update public docs and mark phases Done.

Implemented: reconcile trash/purged lists (API + UI serialization); docs
(`document-lifecycle`, `api`, `reconciliation`, `testing`, `frontend`,
`product-identity`, roadmap/v0.7 Done markers); expanded
`tests/test_v07_lifecycle.py` and frontend/e2e identity coverage.

## Implemented vs future

v0.7 implements lifecycle categories, Documents | Knowledge Explore, Evidence
trash semantics, Master Data safeguards (merge placeholder only), version-aware
BFF downloads, product identity, and collection reconcile lists.

The broader product-experience vision (global graph viewer, Perspectives,
timelines, full merge UI, multi-user ACL layers) remains **future direction** —
see [product-experience-spec.md](product-experience-spec.md) and the defer list
below. Do not document those as shipped behavior.

## Tests required before merge

- Evidence, Master Data, and Organizational lifecycle rules
- Move to trash, restore, and permanent delete authorization
- Tombstone visibility and no metadata leakage
- Replacement preserves entity UUID and relationships
- Failed replacement leaves the old reference intact
- New logical document creates a new entity
- Merge/redirect contract (placeholder) is honest and non-destructive
- Explore entity results and canonical card rendering
- Preview/download and version-aware download authorization
- Collection reconciliation with active, trashed, and purged documents
- Semantic completeness on create, relationship add/remove, replace, archive, restore
- Mobile, keyboard, loading, empty, error, and destructive-confirmation states

## Acceptance criteria

1. AtlasDocs has a clear Home, Explore, Classify, and Ingest product structure.
2. Explore uses canonical entity cards and returns semantic entities.
3. Documents remain evidence while Paperless remains document authority.
4. Lifecycle category controls permitted operations.
5. Evidence replacement preserves Atlas identity and relationships.
6. New real-world documents create new Atlas entities.
7. Paperless trash and purge states reconcile safely.
8. Master Data cannot be casually deleted while relationships exist.
9. Semantic completeness is assigned and recalculated during creation and mutation.
10. No inaccessible Paperless metadata leaks through navigation, search, counts, or relationships.
11. Full backend, frontend, browser, migration, and Docker tests pass.
12. Documentation accurately describes current behavior versus future vision.
